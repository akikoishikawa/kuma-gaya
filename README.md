# くまガヤ（kuma-gaya）

展示ブースの「話しかけてくる熊のぬいぐるみ」用 Web アプリ。
ぬいぐるみの中に仕込んだ iPhone（XR / iOS 18 / Safari）のカメラで人の接近を検出し、
あらかじめ用意した音声（定型フレーズ）を再生して来場者の足を止めます。

- 静的 HTML/JS のみ。ビルド不要
- 人検出：MediaPipe Object Detector（EfficientDet-Lite0 int8）。WASM とモデルはリポジトリに同梱（CDN 不使用）
- Service Worker で全アセット（音声含む）をキャッシュ。**初回読み込み後は機内モードでも動作**
- 会話機能はなし。通信もしない

---

## 構成

```
js/detector.js         MediaPipe Object Detector（person のみ）

vendor/mediapipe/      @mediapipe/tasks-vision 1.2.0（Apache-2.0）の bundle と WASM（SIMD 版）
models/                efficientdet_lite0.tflite（int8）、blaze_face_short_range.tflite
icons/                 アプリアイコン（ツキノワグマ）。icon.svg が元絵で、PNG は次のように書き出す
                       qlmanage -t -s 512 -o /tmp icons/icon.svg → sips で JPEG を経由して透明をなくし icon-512.png、sips -z 180 180 で icon-180.png

```

## 動作

```
待機 ─(こっちを向いた)─→ あいさつ再生 ─┐
待機 ─(接近 or 滞在)──→ 呼びかけ再生 ─┴→ 2段目待ち ─(残っている or こっちを向いた)→ 2段目再生 → クールダウン → 待機
                                                 └─(いなくなった)────────────────────────→ クールダウン
```

| 項目 | 初期値 | 内容 |
|---|---|---|
| 検出間隔 | 250 ms（約4fps） | 毎フレームではなくこの間隔で検出（発熱・電池対策） |
| 反応する範囲 | 35% | 人の枠の面積が画面のこの割合より小さい人（遠い人）はいないものとみなす。下の「反応する範囲を合わせる」で実測して決める |
| 接近しきい値 | 50% | 範囲内でこの割合を超えたら、滞在を待たずにすぐ呼びかけ |
| 滞在時間 | 1.5 秒 | 範囲内の人が連続してこの時間検出されたら呼びかけ |
| 2段目待ち | 6 秒 | 呼びかけ後、人がこの時間残っていたら「2段目」を再生（0 で 2段目なし） |
| クールダウン | 25 秒 | 話し終えてからこの時間は呼びかけない |
| こっちを向いたら反応 | ON | 待機中は「こんにちは！」などのあいさつ、呼びかけ後は待ち時間を待たずにすぐ2段目へ |
| こっちを向いている時間 | 0.5 秒 | この時間正面を向いていたら「こっちを向いた」とみなす |
| 正面とみなす範囲 | 0.25 | 鼻先のずれ÷両目の間隔。大きいほど斜めでも反応する（詳細設定） |
| 見失いの猶予 | 800 ms | 一瞬検出が途切れても「いる」とみなす時間（詳細設定） |

- フレーズはカテゴリ内でシャッフル再生。全部流したら再シャッフル（直前と同じものは続けない）
- 再生中は次の再生を始めない
- 再生回数はカテゴリ別・フレーズ別・きっかけ別（こっちを向いた／接近／滞在／居残り／向いて2段目）に記録

### 反応する範囲（遠い人には話しかけない）

通路の向こう側のブースにいる人に話しかけないよう、**小さく写っている人は無視**します（あいさつ・呼びかけ・2段目・顔の向きのどれにも使わない）。
カメラは距離を直接測れないので、人の枠の大きさ（画面に占める面積）で近さを見ています。

iPhone XR のカメラ（前面・背面とも広角で画角はほぼ同じ）・縦向き・ぬいぐるみの高さ約 1m の場合の目安（大人。体格・姿勢・カメラの高さで変わる）：

| 距離 | 枠の面積 |
|---|---|
| 1m | 40〜50% |
| 1.5m | 約 30% |
| 2m | 約 17% |
| 3m | 約 8% |

初期値 35% はおよそ 1.2〜1.3m です。

#### 反応する範囲を合わせる（会場に置いたら最初にやる）

ここに立った人より遠い人（小さく写る人）には話しかけなくなります。同じ手順は設定パネルの「反応する範囲を合わせる」にも書いてあります。

1. スタートした状態で設定パネルを開き、「反応する範囲を合わせる」の **いまの立ち位置を境目にする** を押す
2. 5 秒以内に、ぬいぐるみから反応させたい距離（例：1m）に、ぬいぐるみの方を向いて立つ
3. 「ピッ」から 3 秒間測り、「ピピッ」で終わり。そのまま動かずに待つ
4. 測った大きさより 1 割小さい値が「反応する範囲」になる（その位置に立った人は確実に含まれる）

- 測る間は、ほかの人が近くに写らないようにする
- 子ども向けなら子どもに立ってもらう（大人で合わせると、子どもはもう少し近づかないと反応しない）
- 結果は設定パネルの上に表示され、「動作」の「反応する範囲」に入る
- 横向き・しゃがんでいる人も小さく写る
- 一度範囲に入った人は、境目の 6 割の大きさまで下がっても「いる」と扱う（話しかけられて一歩下がっても続きを話せるように）
- 2段目を待っている間は、人の検出が 2 秒途切れるまで「いる」と扱う（近すぎて体の一部しか写らないと検出が途切れやすいため）
- 画面では、範囲外の人の枠は **灰色の点線**、範囲内は水色、接近しきい値を超えると赤（デバッグ表示 ON なら枠の大きさ%と「遠い」も出る）

### 「こっちを向いた」の見方

- MediaPipe Face Detector（BlazeFace short range）で顔の目・鼻の位置を取り、鼻先が両目の真ん中にあれば正面とみなす
- 人の枠の上のほう（頭のあたり）を切り出して拡大してから顔を探す。人が画面の数%の大きさでも拾える
- 発熱対策のため、反応する範囲に人がいるときだけ顔を調べる（大きい順に 2 人まで）。クマ耳と鼻もそのときだけ出る（遠い人には出ない）
- 「目が合った」「こっち向いたね」とは言わない（気味が悪いので）。待機中はふつうのあいさつ、呼びかけ後は案内を早めるだけ
- 横顔・うつむき・マスク・逆光では拾えないことがある。そのときは従来どおり接近／滞在で呼びかける

## 画面と設定パネル

- 起動画面の **スタート** をタップ → カメラ開始＋音声のアンロック（iOS の自動再生制限対策）＋画面スリープ防止
- 動作中は **インカメラの映像を全画面に表示** し、検出結果を重ねて描く
  - 人の枠（範囲外＝灰色の点線／範囲内＝水色／接近＝赤）
  - **くまに変身する鏡**：範囲内の人の頭にクマ耳、鼻にクマの鼻を重ねる。両目の位置から大きさと傾きを合わせる（顔の検出は 1 秒に約 4 回なので、速く動くと少し遅れてついてくる）
- クマが話している間は、画面の上に **セリフの吹き出し** を出す（設定パネルのテスト再生でも出る）
  - 前面カメラのときは鏡のように左右反転して表示
  - 映像は画面いっぱいに拡大し、はみ出た端は切れる
- 全画面：iPhone では **ホーム画面に追加したアイコンから起動** すると全画面になる（Safari のページのままではアドレスバーが残る。iPhone の Safari はページの全画面表示に対応していない）。PC・Android・iPad はスタートを押すと全画面になる
- **画面左上の隅（約 90×90pt）を 3 回続けてタップ** → 隠し設定パネル
  - 検出間隔／反応する範囲（立ち位置から実測するボタンつき）／接近しきい値／滞在時間／2段目待ち／クールダウン／音量／前面・背面カメラ（既定は前面）／こっちを向いたら反応・その時間／デバッグ表示
  - 読み上げフォールバック ON/OFF（音声ファイルがないとき Web Speech API で代用。**本番は OFF**）
  - 詳細：検出の信頼度、正面とみなす範囲、見失いの猶予、CPU/GPU
  - 最近の動き（人が来た／再生した／いなくなった／休み、を新しい順に 40 件。2回目が出なかったときなどの原因調べ用。開き直すと消える）
  - テスト再生、再生回数の確認・リセット、フレーズごとの音声の有無、オフライン準備状況
  - 設定は localStorage に保存（次回起動時も同じ）
- デバッグ ON：映像と検出結果に加えて、枠の面積%／信頼度・状態（待機／再生中／2段目待ち／クールダウン残り秒）・鼻のずれ・検出時間と fps

## 音声ファイル

`phrases.json` に 1 フレーズ 1 行で定義し、`audio/` にファイルを置きます。

```json
{ "id": "call_01", "category": "call", "file": "call_01.wav", "text": "こんにちは！ちょっとだけ寄っていってよ" }
```

- `category`：`look`（こっちを向いたときのあいさつ）／`call`（呼びかけ）／`followup`（2段目）
- `tts`（任意）：読み上げ用の文字。イントネーションや読みがおかしいときに、`text` はそのままでここだけ変える（例：「熊対策」→「くま対策」）
- 形式は WAV 推奨（mp3 / m4a も可。`file` の拡張子を合わせる）
- 音声ファイルがないフレーズは、読み上げフォールバックが ON なら `text` を読み上げ、OFF なら選ばれません
- 音声を足したり差し替えたりして配信し直すときは、**`sw.js` の `VERSION` を上げる**（端末のキャッシュを入れ替えるため）

### Gemini の声で一括生成する

既定は Google Cloud Text-to-Speech の Gemini TTS（`gemini-2.5-flash-tts`）です。
kinetone の `@kinetone/voice` と同じ方式で、認証は gcloud、課金先はプロジェクトを明示します。

```bash
gcloud auth application-default login          # 初回だけ（ブラウザでサインイン）
GOOGLE_TTS_PROJECT=kinetone node tools/gen-tts.mjs                  # 未作成のものだけ生成
GOOGLE_TTS_PROJECT=kinetone node tools/gen-tts.mjs --only call_02   # 指定したものだけ作り直す
GOOGLE_TTS_PROJECT=kinetone node tools/gen-tts.mjs --only call_01 --voice Achird   # 声を試す
node tools/gen-tts.mjs --dry-run                                    # 送信内容だけ確認
```

- 課金先のプロジェクトでは `texttospeech.googleapis.com` と `aiplatform.googleapis.com` を有効にしておく（`kinetone` は有効済み）
- **作り直しは `--only` で 1 件ずつが基本。**声は生成のたびに少し変わるので、`--force` で全部作り直すと気に入っていた音声まで変わります
- 声・話し方・速さの既定値は `tools/tts.config.json`（全フレーズ共通）
  - `voice`：既定 `Umbriel`（男性・Easy-going）。ほかの男性の声は `Puck`（Upbeat）、`Achird`（Friendly）、`Sadachbia`（Lively）、`Fenrir`（Excitable）など
  - `style`：話し方の指示（英語のほうが効く）。本文はそのまま読ませ、話し方だけを指示する文に組み込んで渡します
  - `rate`：読む速さ（既定 0.9 ＝ 少しゆっくり）
- 作ったあと自動で確かめ、だめなら最大 4 回まで録り直します（kinetone-aiube の検査を移植）
  - 末尾が大きいまま終わっている（途中で切れている）
  - 途中に 0.8 秒以上の無音がある（頼んでいない一言が足された疑い）
  - 文字数のわりに長すぎる
- 出力は 24kHz・モノラル・16bit の WAV
- API キーで Gemini API から作る場合は `GEMINI_API_KEY=... node tools/gen-tts.mjs --provider gemini-api`
  （Interactions API・`gemini-3.8-flash-tts`。2026年11月時点のドキュメントに合わせたもので、実際には試していません）

## ローカル開発

Node 18 以上があれば、追加のインストールは不要です。

### PC のブラウザで確認（HTTP）

```bash
node tools/serve.mjs
```

http://localhost:8000/ を開きます。`localhost` は HTTPS でなくてもカメラが使えます。
Service Worker のキャッシュが邪魔なときは `http://localhost:8000/?nosw` で開きます（登録しない）。
登録済みのものは、開発者ツール > Application > Service Workers で解除します。

### iPhone 実機で確認（HTTPS）

iPhone からカメラを使うには HTTPS が必要です。2 通りあります。

**A. mkcert で LAN 内 HTTPS（Service Worker まで確認できる）**

```bash
brew install mkcert
mkcert -install
mkdir -p certs
mkcert -cert-file certs/cert.pem -key-file certs/key.pem localhost 127.0.0.1 $(ipconfig getifaddr en0)
node tools/serve.mjs --https
```

1. `mkcert -CAROOT` で表示されるフォルダの `rootCA.pem` を AirDrop で iPhone に送る
2. iPhone：設定 > 一般 > VPN とデバイス管理 → プロファイルをインストール
3. 設定 > 一般 > 情報 > 証明書信頼設定 → mkcert のルート証明書を ON
4. iPhone（同じ Wi-Fi）の Safari で `https://<表示された PC の IP>:8443/` を開く

`certs/` は `.gitignore` 済みです。iPhone のルート証明書は確認が終わったら削除してください。

**B. Cloudflare Tunnel（証明書の準備がいらない）**

```bash
brew install cloudflared
node tools/serve.mjs
cloudflared tunnel --url http://localhost:8000
```

表示された `https://xxxx.trycloudflare.com` を iPhone で開きます。URL は毎回変わるので、
展示本番用ではなく動作確認用です（オフライン用キャッシュは URL ごとに別になるため）。

## デプロイ（GitHub Pages）

1. GitHub にリポジトリを作って push
   ```bash
   gh repo create kuma-gaya --private --source . --push
   ```
   （GitHub Pages を private リポジトリで使うには有料プランが必要。無料なら `--public`）
2. GitHub の Settings > Pages > Build and deployment
   - Source：**Deploy from a branch**
   - Branch：`main` / `/(root)` → Save
3. 数分後に `https://<ユーザー名>.github.io/kuma-gaya/` で公開されます

ほかの静的ホスティング（Cloudflare Pages、Netlify、Firebase Hosting など）でも、リポジトリのルートをそのまま配信すれば動きます。

iPhone ではアプリを開いた状態で設定パネル >「音声・アプリを更新」を押し、アプリを開き直すと反映されます。

## iPhone の準備（展示用）

### 1. ホーム画面に追加して全画面で起動する

1. Safari で公開 URL を開く
2. 共有ボタン（□↑）>「ホーム画面に追加」> 追加
3. 以後はホーム画面の「くまガヤ」アイコンから起動（アドレスバーなしの全画面）

**注意：ホーム画面のアプリは Safari とキャッシュ・設定が別管理です。**
オフライン準備は必ず「ホーム画面のアイコンから起動した状態」で行ってください。

### 2. オフライン準備（展示の前日まで、Wi-Fi のある場所で）

1. ホーム画面のアイコンから起動 → スタート → カメラを許可
2. 一度アプリを閉じて開き直す（Service Worker が有効になる）
3. 左上を 3 回タップ → 設定パネルの「オフライン準備」が
   **「機内モードでも動作できます」**・音声ファイルが全部（例：11/11）そろっていることを確認
4. 機内モードにして、アプリを閉じて開き直し、スタート → 呼びかけまで動くことを確認

### 3. 自動ロックを切る

アプリは Screen Wake Lock API で画面スリープを防ぎますが、念のため本体設定でも切ります。

- 設定 > 画面表示と明るさ > 自動ロック > **なし**
- 設定パネルの「画面ロック防止」が「失敗」「非対応」のときは、この設定が必須です

### 4. アクセスガイドで固定する（ほかの操作をされない・誤ってアプリが閉じない）

1. 設定 > アクセシビリティ > アクセスガイド > ON
2. 「パスコード設定」でアクセスガイド用パスコードを設定
3. 同じ画面の「画面の自動ロック」を **なし**（本体の自動ロックとは別設定なので注意）
4. くまガヤを起動してスタートしたあと、**サイドボタンを 3 回押す** → 右上の「開始」
5. 終了するときはサイドボタンを 3 回押してパスコードを入力 >「終了」

アクセスガイド中も画面左上 3 回タップの設定パネルは使えます。

### 5. そのほか

- **音量**：本体の音量ボタンで最大近くに。アプリ側の音量は設定パネルで調整
- **消音スイッチ**：iOS 16.4 以降はアプリ側で鳴るよう指定していますが、念のため消音を解除
- **明るさ**：映像を見せる必要がなければ低めに（発熱・電池対策）
- **低電力モード**：OFF 推奨（処理が間引かれて検出が遅れることがある）
- **電源**：展示中は給電しながら使う。ぬいぐるみの中は熱がこもるので、ケーブルの取り回しと放熱に注意
- **通知**：集中モード（おやすみモード）で通知や着信の割り込みを止める
- **カメラの向き**：既定は前面カメラ（インカメラ。画面とカメラが同じ側を向き、映っている自分を見られる）。背面にしたいときは設定パネルで切り替え

## 実機での動作確認手順

1. 設定パネルでデバッグ表示を ON（枠の大きさ%や状態の文字が出る）
2. 確認すること
   - 人がフレームに入ると枠が出る（範囲外は灰色の点線、範囲内は水色、接近しきい値を超えると赤）
   - 通路の向こう側の人は灰色の点線のままで、呼びかけない
   - 状態が「待機 → 再生中 → 2段目待ち → 再生中 → クールダウン → 待機」と進む
   - クールダウン中は人がいても呼びかけない
   - 2段目待ちの途中で離れるとクールダウンに移る
   - 「検出」の ms と fps（設定どおりの fps が出ていれば OK。1回の ms が検出間隔に近いときは間隔を延ばす）
3. 置き場所で調整
   - まず「反応する範囲を合わせる」で境目の距離を実測する
   - 遠くの人に反応する → 反応する範囲を上げる
   - 近くの通りすがりにも反応しすぎる → 接近しきい値を上げる／滞在時間を延ばす
   - なかなか反応しない → 反応する範囲を下げる／信頼度を下げる（詳細設定）
   - 枠がちらつく → 見失いの猶予を延ばす
4. 発熱の確認：デバッグ OFF で 30 分〜1 時間置き、本体が熱くなりすぎないか確認。
   熱いときは検出間隔を 400〜500ms（2〜2.5fps）に延ばす。CPU/GPU の切り替えで軽くなる場合もある
5. 展示後：設定パネルの「再生回数」をスクリーンショットして記録 →「回数をリセット」

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 「カメラが許可されていません」 | 設定 > Safari > カメラ を「確認」か「許可」に。ホーム画面アプリは起動ごとに許可を聞かれることがある |
| 音が鳴らない | 本体の音量・消音スイッチを確認。スタートをタップせずに起動していないか。設定パネルの「音声」が `running` か |
| しばらくすると止まる | 自動ロック（本体設定とアクセスガイドの両方）が「なし」か。アプリを裏に回すとカメラが止まる（戻ると自動で再開） |
| 機内モードで開けない | ホーム画面のアイコンから一度オンラインで起動したか（Safari とは別管理）。設定パネルのオフライン準備を確認 |
| 音声を差し替えたのに古いまま | `sw.js` の `VERSION` を上げて配信し、設定パネル >「音声・アプリを更新」→ 開き直す |
